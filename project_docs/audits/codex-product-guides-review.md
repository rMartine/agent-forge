# Guías de producto: diseño y compatibilidad técnica

Revisión realizada el 2 de octubre de 2026, con resultados de ejecución registrados también en UTC el 3 de octubre. Este documento complementa la [revisión inicial de seis skills](codex-skill-selection.md). No vuelve a atribuir a esa revisión resultados de las candidatas posteriores ni acredita una instalación en Desktop o VS Code.

## Alcance y evidencia

El encargo pide guías útiles para construir productos con la dirección técnica en el agente principal. Se revisaron las candidatas originales de Impeccable, Emil Kowalski y Taste, y una selección de guías para las tecnologías indicadas. La búsqueda de candidatas se hizo mediante skills.sh; las que se incorporan se inspeccionaron después en sus repositorios originales. La lista no representa una revisión exhaustiva del catálogo y no demuestra superioridad universal.

Las versiones de Liravo y Skillara indicadas en el encargo son condiciones que la guía debe comprobar en el repositorio al activarse: Expo 54, React Native 0.81.5, Reanimated 4.1.1, Worklets 0.5.1, Gesture Handler 2.28, Haptics 15; Next.js 15.5, React 19 y Tailwind CSS 4. Las guías de servidor contemplan Express 5, Yoga 5, Pothos 4, Drizzle 0.45, PostgreSQL 16, BullMQ 5, Valkey y OpenAI Agents para TypeScript 0.11.8. Esto no afirma que se hayan inspeccionado o ejecutado esos productos durante esta revisión de Agent Forge.

## Candidatas de diseño preparadas

Las seis siguientes incorporaciones son derivados editoriales identificados como tales, preparados para la comparación de comportamiento y diseño. La revisión estática confirma sus recursos y contratos; la calidad visual exige la comparación de tres casos. El [informe de esos materiales](codex-design-guide-comparison.md) registra el rechazo del navegador y no afirma ejecución visual. Anthropic frontend-design permanece como guía general vigente. Impeccable queda explícitamente limitada a una solicitud de uso o comparación de Impeccable dentro de un encargo autorizado; no se activa por una tarea general de interfaz. Su descripción, condición de activación e instrucciones adaptadas expresan esa limitación. La habilitación definitiva y las observaciones de clientes se resuelven en la integración; esta auditoría no las acredita.

## Verificación realizada y límites

Se ejecutó `node --test scripts/review-product-guides/verify.test.mjs`: dos casos aprobados, que rechazan sustituciones sobre una fuente cambiada o ambigua y detectan referencias transitivas ausentes/fuera del paquete. El verificador distingue enlaces reales de ejemplos escritos como código.

Se ejecutó `node scripts/review-product-guides/verify.mjs .cache/review-product-guides/static-verification.json` usando el renderer real compilado de core y descargas deshabilitadas. La evidencia guarda hashes fuente/renderizado de cada SKILL, revisión, licencia, conteos, asignaciones y hash del catálogo. Al preparar las doce entradas actuales se resolvieron 161 archivos originales y 173 archivos renderizados, sin enlaces locales faltantes. Los bytes de las licencias se conservan.

Se intentó `skill-creator/scripts/quick_validate.py` con el Python incluido en Codex, pero no pudo iniciarse porque falta PyYAML. No se instaló esa dependencia. El verificador Node usa el parser YAML existente y comprueba el mismo contrato relevante: frontmatter, campos, identidad, límites de nombre/descripción y ausencia de TODO incompletos, además de enlaces y recursos. Este resultado debe describirse como comprobación equivalente propia, no como ejecución exitosa de quick_validate.

Se prepararon seis fixtures YAML de activación explícita/implícita/negativa y once escenarios de versiones, herramientas ausentes, datos, autorización y Graphify. Son entradas con comportamiento esperado; no son ejecuciones observadas de agentes. La comparación visual de tres casos, la instalación, la confianza de hooks y la observación de Desktop/VS Code se registran por separado. Ningún resultado estático de este documento las sustituye.

## Reproducción y recuperación

El catálogo contiene revisiones completas y hashes por recurso; su cache se reconstruye solo desde esas revisiones con comprobación de integridad. Los planes de instalación resuelven estos bytes antes de aplicar. La revisión de guías no instala ni registra hooks directamente. Para retirar una selección se modifica el catálogo y se regenera un plan de Agent Forge, conservando respaldo/recuperación y cambios ajenos según el instalador. No se borran manualmente carpetas de perfiles.
