# Documentation Quality

- Write for the actual audience and current repository behavior.
- Link requirements, architecture decisions, implementation, tests, release, and rollback evidence where those relationships matter.
- Validate commands, paths, file names, anchors, and external links when practical.
- Label assumptions and unverified claims.
- Never place credentials, private data, real environment files, or unverifiable success claims in documentation.
